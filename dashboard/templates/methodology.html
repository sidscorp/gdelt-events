Methodology

Exactly how everything on this dashboard is selected, ranked, and written — nothing hidden.

The data

Every 15 minutes the pipeline ingests the newest batch from the GDELT Project's Global Article List (~44,000 outlets worldwide). Articles are kept for a rolling 60 days. GDELT's crawl runs roughly 1–2 hours behind real-time publication, so brand-new stories first appear as single articles and accumulate their "covered by N sources" counts as syndication is crawled.

Event cards ("covered by N sources")

Every English article is embedded with a local neural model (nomic-embed-text, running on our own GPU). A clustering pass groups near-duplicate articles about the same event, so the feed shows one card per event instead of the same headline dozens of times. The card links every member article.

How the feed is ordered (Importance sort)

The default "Importance" ordering ranks each event in your selected time window by a composite score:

  • Coverage (weight 0.5) — log(1 + number of sources covering the event). More outlets = more important.
  • Recency (weight 0.3) — exponential decay with a 12-hour half-life-style constant: a 12-hour-old event keeps ~37% of its recency weight.
  • Velocity (weight 0.2) — sources per hour since the event first appeared. Rewards stories breaking fast.

Each component is normalized within the current window's candidates, then combined. "Newest"/"Oldest" bypass this entirely and sort by crawl time. There is no editorial input and no personalization — every visitor sees the same ranking.

How topic pills decide what belongs (since July 2026)

Each curated topic pill works in two stages:

  1. Nomination (recall) — an article becomes a candidate for a pill if it matches the pill's keyword list, appears in the FDA-registered manufacturer name index (Medical Device Companies only), or its embedding is semantically close to the pill's topic description.
  2. Judgment (precision) — every candidate is then read by an LLM judge (gpt-oss-120b, an open-weights model, called via our self-hosted gateway) which answers one question: does this article actually belong to this topic? Only judge-approved articles get in. For the noisiest topics (Supply Chain, Medical Device Companies, AI & Defense, OSS Vulnerabilities) borderline verdicts are rejected too.

This replaced pure keyword matching in July 2026 after a blind LLM audit measured how often each pill's articles were actually on-topic: Supply Chain scored 25% and Medical Device Companies 11% under keywords alone; after judge-gating, every pill measures roughly 75–94%. Every article's inclusion reason is stored and shown as a badge on its card in pill views (judge verdict + semantic similarity, or the matched keyword for non-English articles, which skip the judge).

Custom pills (for signed-in users) use pure semantic matching against your written description at the strictness you choose — no LLM judge, so expect a bit more noise than the curated pills.

How the AI briefing is written

When you open a briefing for a view + time window:

  1. The system takes the top 50 events by the same Importance score as the feed — the briefing summarizes exactly what the feed shows.
  2. A prompt is built containing: the 50 numbered events (title + summary + outlet + source count, explicitly marked as importance-ranked), the titles the previous briefing covered (so the model writes progressions instead of re-explaining), any ongoing story threads it has been tracking, and a hard rule that the top-5 events must be covered.
  3. The prompt is sent to GLM-4.7 on Cerebras (a fast open-weights model via our self-hosted gateway). Citations like [3] link back to the exact numbered event.
  4. The result is cached for 45 minutes per view/window — the "cached" label and timestamp are shown under each briefing.

Click the ⓘ on any briefing to see everything that generation used: the model, the full ranked source list, the continuity context, and the verbatim prompt.

What the AI does not do

  • No model chooses which articles enter the database or the global feed — that's coverage math only.
  • Briefings can only cite the numbered events they were given; they are instructed never to invent numbers or URLs.
  • No personalization, tracking-based ranking, or engagement optimization anywhere.
