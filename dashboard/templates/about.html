About GDELT Monitor

A global news monitor that reads everything, so you don't have to.

What it does

Every 15 minutes the pipeline pulls the newest batch from GDELT's Global Article List and Global Knowledge Graph — roughly 44,000 news outlets worldwide. Articles land in a DuckDB analytical database and are scanned by three independent systems: keyword pattern matching, entity recognition against reference registries, and semantic embeddings from a neural model running on local hardware.

Keywords proved out to be too rough for the hard topics: when audited, they scored 11–25% precision. So every candidate article is now read by a language model that answers one question: does this actually belong to this topic? Only approved articles get in, and each one carries its reason. That single change moved the curated feeds to a measured median of {{ eval_median or '76%' }} precision (range {{ eval_min or '56%' }}–{{ eval_max or '95%' }}). Signed-in users can also define their own topics in plain English, matched semantically.

A major story gets reported by hundreds of outlets at once, so near-duplicate articles about the same event roll up into a single event card — each with a shareable permalink — and the feed shows distinct stories instead of the same headline forty times. For any topic and time window, an AI briefing summarizes what's actually happening across the matched coverage, with citations back to the specific numbered sources it was given. There's semantic search too: describe what you're looking for and it finds articles by meaning rather than exact words.

How it works

Articles are scanned using Aho-Corasick automata — a trie-based algorithm that finds all occurrences of thousands of patterns in a single linear pass. Matches are materialized into indexed cache tables so the dashboard serves results in under a second. The system keeps a rolling 60-day window and prunes older data to bound storage. New articles are classified every 15 minutes.

Alongside keyword matching, each English article is embedded with a local neural model (nomic-embed-text via Ollama, on our own GPU — no article text leaves the building for this) and indexed in a FAISS vector store. A leader-clustering pass groups articles whose embeddings are near-duplicates into persistent event clusters — this is what powers the rolled-up event cards and their permalinks. The AI briefings are generated on demand from the top events in a view by {% if model %}{{ model }}{% else %}an open-weights model{% endif %} — served by a hosted inference provider (Fireworks) and reached through our self-hosted LiteLLM gateway; the gateway is ours, the model hardware is not — streamed token-by-token and cached so repeat views load instantly. Topic pills are precision-gated by an LLM judge — see the methodology page for the full logic behind everything displayed.

The tech stack

  • Data source GDELT Project v2 (GKG) + v3 (GAL)
  • Database DuckDB 1.5.1 (analytical) + SQLite (user data)
  • Pattern matching Aho-Corasick via pyahocorasick
  • Embeddings nomic-embed-text v1.5 via Ollama
  • Event clustering FAISS IVF-PQ + exact-cosine re-rank
  • AI briefings {{ model or 'open-weights model' }} — Fireworks-hosted, via self-hosted LiteLLM gateway
  • Web framework Flask + Waitress
  • App Installable PWA (service worker)
  • Infrastructure Cloudflare Tunnel (zero-trust)
  • Language Python 3.13
  • Hosting Self-hosted, NVIDIA RTX 4060
